# Decisions

Choices the brief (`SPEC.md`) doesn't make, with the reasoning. Newest at the bottom. Raise anything here in review; nothing is expensive to undo yet.

## Phase 0

1. **Prisma 6, not 7.** Prisma 7 requires driver adapters and a `prisma.config.ts`; switching database then means swapping an adapter in code. Prisma 6 keeps the "boring" setup the brief describes: `DATABASE_URL` in `.env`, `file:./dev.db` in dev. Moving to Postgres is one line in `prisma/schema.prisma` (`provider = "postgresql"`) plus the URL. No dialect-specific attributes are used.
2. **Prisma enums are used for every status field** (validated on SQLite with `prisma validate` and the init migration). They map to `TEXT` on SQLite and native enums on Postgres with no schema edits.
3. **Schema additions beyond spec section 4**, all nullable or defaulted:
   - `BankAccount.userId` is nullable so organisation accounts can exist without a user (Organisation → BankAccount).
   - `BankAccount.changedAt` drives the 24h receiving cooling-off.
   - `Payment.payerUserId` is nullable and `Payment.payerDisplayName` exists for people who pay a collection from the public web page without an account.
   - `PaymentRequest.lastRemindedAt` backs the once-per-24h reminder rate limit.
   - `User.deletedAt`, `User.phoneE164`/`phoneHash` nullable: account deletion blanks the phone fields and keeps the row so `Payment` history can be anonymised rather than deleted.
   - `OtpChallenge.consumedAt`, `Session.lastUsedAt`: bookkeeping.
4. **Endpoints the UI needs that section 5 doesn't list** (to confirm in Phase 1): `GET /me` returns the profile, a bank *summary* (bank name, CoP status, cooling-off end; never account identifiers) and the current limits; `GET /requests?role=incoming|outgoing`; `GET /orgs` returns organisations with collection summaries. List responses use an envelope (`{ "payments": [...] }`) so metadata can be added later. Payments carry a `counterparty { userId, displayName }` so the feed can render without a second lookup.
5. **Limits live in `backend/src/limits.ts`** and are returned by `GET /me`, so the app shows what the server enforces instead of hard-coding them.
6. **Fastify's logger is configured with options**, not a pino instance: Fastify 5.12's `loggerInstance` type does not accept pino 10's `Logger`. Services receive `app.log` (or a child) as a parameter.
7. **vitest 4.0.18.** vitest 5 requires Node 22 (the brief says Node 20); vitest 4.1 trips an npm 10 peer-resolution bug that breaks a clean `npm ci`.
8. **Xcode project is hand-written** using Xcode 16's file-system-synchronized groups, so adding a Swift file to a folder adds it to the target with no project edits. No XcodeGen. Bundle identifier placeholder: `com.quid.app`.
9. **Two shared schemes:** `QuidApp` (live backend at `localhost:3000`) and `QuidApp-Mock` (`-mock` launch argument). `QUID_API_BASE_URL` overrides the base URL.
10. **MockMode is a `URLProtocol`**, not a second client. The real `APIClient`, JSON decoding and error mapping run in the demo and in tests; only the transport is faked. Fixtures build dates relative to "now" so Today/Yesterday grouping stays realistic.
11. **The app's entry type is `QuidMain`**, not `QuidApp`, so a type never shadows the module name (`QuidApp.Foo`).
12. **Design tokens not in the brief:** failure tint `#FBE8E6` / text `#9A2B1F`; cards are white (`#FFFFFF`) on the `#F6F7F5` background; a secondary fill `#EEF1EF` for secondary buttons and icon tiles. In dark mode surfaces invert and the accent fill stays `#0B6B54`; small accent *text* lightens to `#6CCBAA` to keep 4.5:1 contrast. Letter-spacing is −2 on hero/large amounts and −0.5 on inline amounts (−2 is unreadable at 17pt).
13. **Avatar tints** are six muted background/foreground pairs chosen by a stable FNV hash of the name, so a person keeps their colour across launches and screens.
14. **`NSAllowsLocalNetworking`** is set so the live scheme can reach `http://localhost:3000` on the simulator without disabling App Transport Security generally.
15. **Phase 0 includes a UI shell** for the four tabs on canned data (slightly beyond "scaffold") so the design system could be reviewed as real screens. Later-phase actions open a "Phase N" sheet rather than silently doing nothing.
16. **Repo-root scripts are shell wrappers** that `cd backend`; a TypeScript file in `/scripts` could not resolve `@prisma/client` from `backend/node_modules`.
17. **Legal URLs** are placeholders (`https://quid.example/...`) until real pages exist.

## Phase 0 review fixes

An adversarial review (four lenses, each finding challenged by a skeptic) ran before hand-off; 21 findings were confirmed and fixed. Decisions that came out of it:

18. **System chrome is tinted with `quidAccentText`**, not `quidAccent`: the selected tab, back buttons, toggles, progress bars and the loading spinner need 4.5:1 against dark surfaces, and `#0B6B54` only manages about 2.8:1 there. Filled buttons keep `quidAccent` because their foreground is white (6.5:1). The asset catalog's AccentColor has the same dark-appearance value so UIKit alerts match.
19. **Activity, Collect and Me are card stacks, not `List`s.** `insetGrouped` lists force 10pt corners and SF section headers, which broke the one visual language across tabs. Rows that push a screen draw their own chevron (`QuidChevron`). Navigation titles and segmented controls are set to Manrope via `UIAppearance` (`QuidAppearance.configure()`), scaled with `UIFontMetrics` for the current text size. Appearance proxies are static, so `RootView` re-runs `configure()` when the text size changes mid-session: bars created from then on use the new size, bars already on screen keep theirs until they are recreated (SwiftUI content scales live either way). Rebuilding the tab hierarchy to force it was tried and rejected because it discarded tab selection, loaded data and search state. Known limitation for the Phase 5 accessibility audit. Rows that leave the app (Legal) show an external-link glyph, not a chevron.
20. **Section headers are 44pt tall** so a trailing text action ("See all") always has a full-size hit target; small headers (day groups, settings groups) are 13pt muted Manrope.
21. **Task cancellation is not an error.** `APIClient` turns `URLError.cancelled` into `CancellationError`, and every ViewModel's `load()` returns quietly on it. Switching tabs mid-load no longer flashes a "cancelled" error card.
22. **Loading placeholders are driven by a first-load state, never by "data is nil".** Each ViewModel (Home, Activity, Collect, CollectionDetail, Me) exposes `hasLoaded` and `isAwaitingFirstLoad` (nothing loaded yet and nothing failed), which also covers the first frame before `.task` runs and a load cancelled by leaving the tab. Home's inline recent-contacts line switches to error wording only when the first load failed (`!hasLoaded && error != nil`); a failed refresh with contacts already on screen keeps the neutral text. List sections that own a retry card (Home activity, Activity, Collect, collection detail) show that card whenever a load fails and no items are on screen, including after a successful empty first load, since retry is the right offer in that state. A failed first load shows an error card with retry that stays mounted while the retry runs; `error` is cleared only on success. Account-deletion failures surface in their own alert (`deleteError`) rather than being swallowed.
23. **Pretty logs are an explicit opt-in** (`LOG_PRETTY=1` or `true`; blank, `0` and `false` mean off). `pino-pretty` is a devDependency, so keying it off `NODE_ENV=development` crashed a production start with no fatal log line. `server.ts` imports config, the database module and the app dynamically inside `main()` in that order, so environment validation runs before Prisma Client is constructed, and validation, logger construction and listen failures all go through the one `failed to start` handler.
24. **Log redaction uses explicit paths** (`phone`, `*.phone`, `req.body.phone`, …) generated from one `SENSITIVE_FIELDS` list, and `err.code` is deliberately visible. A test logs representative shapes and asserts exactly what is censored. Add a path when you log a new shape; pino's `*` matches one level only.
25. **The test database is recreated on every `npm test`** and test files run sequentially (`fileParallelism: false`), since they share one SQLite file. The Prisma CLI is invoked via `process.execPath`, which also works on Windows.
26. **`Package.resolved` is committed** (the ignore rule was removed) so Phase 2's SPM dependency on the TrueLayer SDK stays reproducible.
27. **Secondary buttons have a visible pressed state** (`quidSurfaceSecondaryPressed`, `#DFE4E1` light / `#323C37` dark); the previous pressed colour was indistinguishable from resting.
28. **Section headers carry the VoiceOver header trait** so the Headings rotor can jump between day groups, settings groups and organisations now that those screens are cards rather than `List` sections.

## Phase 1

29. **Two-layer phone hashing.** The brief says the app sends hashes, never numbers, and that the pepper lives in `.env`; a server-only pepper means the app cannot compute an HMAC. So the app sends `clientHash = SHA-256(E.164)` (unkeyed; transport hygiene, not a secret, since the number space is small) and the server stores and matches `HMAC-SHA256(pepper, clientHash)`. A database copy is useless without the pepper. The shared test vector for `+447700900123` is `a8acc3a9…1436` on both sides.
30. **OTP.** Six digits from a CSPRNG, HMAC-hashed with the pepper and bound to the phone number, 5-minute TTL, 5 attempts then locked, the newest code supersedes any open one. Per number: 5 codes per 15 minutes. Per IP: 30 auth requests a minute. `/auth/otp/start` answers identically for registered and unregistered numbers, so it cannot probe the directory. Dev mode logs the SMS body (spec section 5); `req.body.code` stays redacted.
31. **Sessions.** 32 random bytes as a base64url bearer token; only its SHA-256 is stored; 30-day TTL (`SESSION_TTL_DAYS`); `lastUsedAt` refreshed at most hourly. `POST /auth/logout` deletes that one session. Expired sessions and deleted users get 401. Keychain holds the token on the phone, memory in MockMode.
32. **Dev stand-ins are refused in production.** `SMS_SENDER=log`, `COP_VERIFIER=fake`, the placeholder pepper and the all-zero key each abort startup when `NODE_ENV=production`.
33. **Confirmation of Payee flow.** `PUT /me/bank-account` runs the verifier first. MATCH stores the details (AES-256-GCM) and answers with the bank summary; CLOSE_MATCH stores nothing and returns the bank's version of the name for the user to accept (the app resubmits with it); NO_MATCH stores nothing. `FakePayeeVerifier` fixtures: sort code `999999` is NO_MATCH; the registry accounts `04-00-04 12345678` (Sam Okafor), `04-00-04 87654321` (Priya Patel) and `23-05-80 11223344` (SOAS Hockey Club) are MATCH only with that exact name and CLOSE_MATCH when it differs by case or spacing; anything else is MATCH so any dev account can be linked.
34. **Providers are a static GB list in Phase 1** (`services/providers.ts`) with TrueLayer-style ids such as `ob-monzo` and no logos; the sandbox mock bank is included when `TRUELAYER_ENV=sandbox`. Phase 2 replaces the source with the TrueLayer providers API (cached 1h) after reading its docs, validates the ids and migrates stored `providerId`s if any differ.
35. **Cooling-off starts on a change, not the first link.** `BankAccount.changedAt` is compared with `createdAt`; `GET /me` reports `coolingOffUntil` only within 24h of a change. Enforcement against payments is Phase 5.
36. **`DELETE /me` ships in Phase 1** (the brief lists it under Phase 5) because the Me screen already offers it: sessions and bank details are deleted, phone fields blanked, the name becomes "Deleted user", `deletedAt` is set, and the number can sign up again as a new user. Anonymisation of `Payment` rows is asserted in Phase 5 once payments exist.
37. **Directory lookup** dedupes hashes, excludes the caller and deleted users, and is limited to 10 requests a minute per user by a limiter that runs *after* auth (`app.rateLimit()` as a preHandler) so it keys on the user id rather than the IP.
38. **`GET /requests` and `GET /orgs` return empty lists** until Phases 3 and 4, so the live app's tabs show real empty states.
39. **Bank linking is skippable** during onboarding ("I'll do this later"). The skip is a per-device flag; Home then shows a "Link your bank to get paid" card and Me offers the same sheet. Linking from either clears the flag.
40. **Onboarding resumes from the profile**, not from device state: after sign-in, `GET /me` decides the next step (empty name, then bank unless skipped, then the contacts explainer flag). `AppEnvironment.onboardingInProgress` keeps the flow on screen while the session appears mid-way, so a verified code does not bounce the user to a loading screen.
41. **Contacts permission is not requested in Phase 1.** The explainer screen describes hashing and defers the system prompt to the first Pay tap (Phase 2), as the brief requires. `ContactsService`, `UKPhone` and `DirectoryService` are built and tested now.
42. **The mock backend is stateful.** `-signed-out` launches on the welcome screen with a fresh mock user; the accepted code is `123456`; sort code `999999` is NO_MATCH and an all-lowercase holder name is CLOSE_MATCH; the directory recognises the demo contacts' numbers. The onboarding XCUITest runs against this.
43. **UK phone normalisation** lives in one function on each side (`lib/phone.ts`, `UKPhone.swift`) with the same table of accepted inputs, because the directory only works if both sides hash exactly the same string.
